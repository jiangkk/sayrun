GETTING STARTED

从这里，开始。

把自然语言任务接入现有 zsh 工作流。
这里是从安装到完成第一个任务的完整指南。

环境要求

环境要求
系统已在 macOS / Apple Silicon 验证；Linux 与其他架构待验证。
终端交互式终端；自然语言输入集成需要 zsh。
Node.js22 或更高版本。
DSH已安装、已认证且位于 PATH 中。使用 sdk-minimal profile，不限制 DSH 版本号。

Sayrun 当前内置 DSH 后端，复用 DSH 已配置的凭证。请先按 DSH 的官方说明完成安装和认证；安装 Sayrun 本身不会安装或登录 DSH。Bun 和 OpenTUI 会随 npm 依赖安装，无需额外全局安装 Bun。

安装与启用

1. 全局安装

npm install -g sayrun-shell

npm 包名为 sayrun-shell，安装后的终端命令为 sayrun。消费者运行构建后的 JavaScript，无需下载源码或手动构建。

2. 配置终端集成

sayrun setup

Setup 会展示计划修改的文件，经确认后备份 zsh 启动文件，只更新 Sayrun 专属标记区块。首次交互式配置后，会进入已启用集成的新 zsh；输入 exit 可返回原终端。已加载集成时，重新运行 setup 会刷新当前集成。

如果只想先看计划，可以运行 sayrun setup --dry-run。如果希望仅完成配置，使用 sayrun setup --no-shell，然后在当前终端手动启用：

eval "$(sayrun shell init zsh)"
sayrun doctor
终端集成只需配置一次，以后新开的 zsh 会自动加载。npm 安装命令本身无法修改父 shell 的回车处理，因此请完成 setup。

第一个任务

在已启用集成的 zsh 提示符中，直接输入你的需求并回车：

帮我找出当前目录最大的十个文件，只读取文件信息

常规命令、别名、函数和多行语法继续交给 zsh。对有歧义的输入，Sayrun 会尝试分类；无法确定时询问你。未启用集成，或需要显式发起任务时，可使用：

sayrun ask "帮我检查当前目录的文件结构"

你也可以先体验离线审批界面，无需模型凭证：

sayrun preview

审批与快捷键

每条新命令执行前，Sayrun 会显示完整命令和执行目录。你可以批准、拒绝，或先编辑命令。任务完成后显示结果与结论，再返回 shell。

按键操作
y / n批准 / 拒绝当前命令。
← → / Tab切换操作，再按 Enter 确认。命令审批默认选中批准。
e进入命令编辑。编辑后按 Enter 默认执行修改后的命令。
Shift-Enter在编辑器中换行。
Ctrl-S仅保存编辑，返回审批。
↑ ↓ / PgUp PgDn滚动命令预览。
Ctrl-C取消任务并恢复终端。
审批机制不等同于操作系统沙箱。默认执行器在本机运行独立的 zsh -f -c，不加载 shell 别名、函数或启动配置；不同命令之间不保留 cd / export。请在批准前检查实际命令。

回看与继续

任务历史按项目保存。你可以在选择器中浏览，也可以搜索、查看、导出，或基于之前的可见历史继续新的请求。

sayrun sessions
sayrun sessions search "构建失败"
sayrun sessions show <会话ID> --full
sayrun resume --last --prompt "根据刚才的结果，再检查一次"

sayrun sessions 中可用方向键选择任务，Enter 查看，Esc 返回 shell。

导出任务

sayrun sessions export <会话ID> --format markdown --output /tmp/task.md

将 <会话ID> 替换为实际 ID。支持 Markdown 和 JSON 导出；--redact 会对常见凭证模式及项目路径做尽力脱敏，分享前仍请检查内容。

当前 DSH 适配器使用可见历史创建新的上下文分支，不会重放旧命令。你提交新的请求后，后续命令仍需重新审批。

配置与诊断

先检查本地环境

sayrun doctor
sayrun backend check dsh
sayrun auth status dsh

默认检查不调用模型。如需在线验证，使用 sayrun doctor --live，这会发送最小模型探测，可能产生用量。

调整界面和执行预算

sayrun config show --effective
sayrun config set agent.max_commands 10
sayrun config set execution.timeout_seconds 60
sayrun config set ui.mode plain
sayrun config set ui.mode opentui

管理命令和任务审批默认使用 OpenTUI。可设置 ui.mode plain 切换纯文本，或用 ui.mode opentui 切回；非 TTY 管理输出使用纯文本，显式 --json 保留机器可读格式。

用户配置默认在 ~/.config/terminal-agent/config.toml。项目配置名为 .terminal-agent.toml，沿用旧版路径以兼容已有数据。项目中的后端、模型、预算等配置需要先运行 sayrun config trust .。

临时关闭与恢复集成

sayrun shell off
sayrun shell on
sayrun shell status

常见问题

安装后为什么自然语言没有生效？+

先运行 sayrun setup，确保当前 zsh 已加载集成。使用过 --no-shell 时，打开新的 zsh，或执行安装章节中的 shell init 命令。可以用 sayrun shell status 查看状态；未启用集成时，使用 sayrun ask 也能发起任务。

需要再次输入 API Key 吗？+

Sayrun 复用 DSH 已配置的认证。先检查 DSH 是否完成认证、是否在 PATH 中，再运行 sayrun auth status dsh。此工具不会接收或打印密钥。

为什么不能运行交互命令？+

当前执行器不支持需要交互输入的命令或后台任务。命令审批在交互式终端进行，实际执行使用独立的 zsh 进程。

如何更新？+

使用 npm install -g sayrun-shell@latest。sayrun update --check 只查询版本，不会自动安装。npm 新版本完成发布扫描后才会出现在官方 registry。

卸载

sayrun shell uninstall --dry-run
sayrun shell uninstall
npm uninstall -g sayrun-shell

先预览卸载改动，再确认移除终端集成。卸载会备份 zsh 启动文件，只移除 Sayrun 标记区块；配置和历史保留。
